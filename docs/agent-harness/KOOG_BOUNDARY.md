# GitHub ↔ Koog boundary and session protocol v1 (#784)

**Status:** reviewed #784 boundary; Koog runtime not activated in social-mcp. Parent: #783. Implementation: #785–#790. **Canonical protocol ownership is now [Recursive Coder](https://github.com/YuriiSokolenko/recursive-coder)**, including [the v1 schema](https://github.com/YuriiSokolenko/recursive-coder/blob/dev/contracts/v1/session-v1.schema.json), [examples](https://github.com/YuriiSokolenko/recursive-coder/blob/dev/contracts/v1/session-v1.examples.json), and its [independent CI](https://github.com/YuriiSokolenko/recursive-coder/blob/dev/.github/workflows/ci.yml). ## Decision and trust boundary

- **social-mcp / trusted GitHub control plane** owns the global queue, dependencies, issue/PR labels and state, workflow triggers, runner allocation, checkout and worktree preparation, trusted final validation, commits/pushes and PR creation, independent PR review publication, CI verdict, Reconciler, Merge Gate, post-merge behavior and N150 autoscaler. It is the only authority for repository-facing transitions. GitHub event payloads and model text are untrusted inputs; trusted scripts re-read current GitHub state.
- **Recursive Coder / Kotlin + Koog one-job execution engine** receives a frozen, authenticated local SessionRequest and executes exactly **one logical session per GitHub Actions job invocation**, with an internal recursive graph of agents, tools, budgets, events, scoped mutations, deterministic checks, side-effect journaling and durable checkpoints. Recursive SDD → ATDD → TDD → Develop → independent Reviewer applies to decomposed subtasks **inside** the session. It does not spawn GitHub issues/jobs or publish global state.
- **Pi / mini-swe** remain fully supported during migration. Koog is a versioned, explicitly enabled backend option, not a reinterpretation of PI_* events or the existing Pi tool surface. A session result is evidence, never a grant of permission to mutate GitHub or skip CI.
- **HP Nano model serving** and its Open Responses-compatible endpoint remain infrastructure. Koog does not choose a different model implicitly, reconfigure model hosting, or bypass the existing loaded-model preflight.

There are **two different reviewers**: recursive child Reviewers check local subtask products without editing ATDD/TDD/SDD-owned specifications or tests; the external GitHub PR Reviewer checks the current PR HEAD and is independently authoritative for PR verdicts. Developer may not edit protected specs/tests created by other stages; a separate reviewed change must authorize any revision.

## Ownership matrix and sequence

| Activity | Trusted GitHub owner | Koog session owner |
| --- | --- | --- |
| Select eligible issue, dependencies, role and runner | **Authoritative** | Can suggest only; no GitHub API mutation. |
| Checkout, clean local worktree, base ref, baseline SHA, locked spec/test inputs | **Creates, verifies, issues scope** | Receives paths and immutable hashes; cannot widen them. |
| Model selection, endpoint and credentials | Chooses configured alias, confirms loaded model, passes credential reference via isolated runner binding | Uses exactly supplied ID/base URL and masked credential; no model fallback. |
| Recursive SDD → ATDD → TDD → Develop → local Review | Supplies task constraints / high-level role | **Owns** child agents, immutable outputs per stage, bounded recursion and journaling. |
| Tool execution and local checks | Issues allow/deny + sandbox policy; **revalidates** acceptance, final checks and worktree changes | Executes only authorized local operations, emits audited events, no privileged GitHub token. |
| Create commit, push branch, publish/repair PR, issue labels | **Only owner**; independent current-HEAD and trusted receipt verification | Returns terminal artifact and candidate local changes only. |
| Independent PR review verdict and CI | **Only owner**; CURRENT PR SHA and required jobs, not model prose | Returns findings/diagnostics, never authoritative PASS or green CI. |
| Merge Gate, post-merge CI, Reconciler and retry routing | **Only owner** | No capability to dispatch or merge. |
| Durable checkpoint/side-effect recovery | Allocates protected store, grants lease, validates worktree, policy/baseline, issues new fence per attempt | Checkpoints safe local state and idempotency journal; refuses unsafe replay. |

**Normal path:** Actions allocates a single job → trusted script reads GitHub and prepares worktree → trusted adapter freezes SessionRequest and restricted environment → selected backend runs one logical session with any internal children → backend writes append-only events, immutable artifact references, terminal SessionResult → trusted adapter validates schemas, request/attempt/fence/baseline/policy and receipts → trusted final tests and diff checks → existing publication/Reviewer/CI/Merge Gate code decides global changes. An exception, missing terminal receipt, unsupported version, corrupt artifact or timed-out job **never** converts into success.

## Protocol v1 / compatibility rules

- Each object is a **versioned JSON envelope**: SessionRequest, SessionResult, SessionEvent or SessionCheckpoint, selected by `kind`; SessionError is a **versioned-by-envelope** nested failure shape. The canonical schema lives at [recursive-coder/contracts/v1/session-v1.schema.json](https://github.com/YuriiSokolenko/recursive-coder/blob/dev/contracts/v1/session-v1.schema.json) (JSON Schema 2020-12); examples are concrete, non-secret sample data, **not** an assertion those historical runs executed Koog.
- `version = MAJOR.MINOR`, initially `1.0`. Any unknown major is rejected before tools run; 1.x readers validate the stable known fields and may ignore unknown namespaced `extensions.x-*` objects, but **must** reject unknown top-level properties and unsupported requiredCapabilities. Minor revisions cannot remove/rename required fields, weaken policy checks or change enum meanings; breaking changes require v2 and explicit negotiation. The writer MUST include a version the reader explicitly supports; there is no silent translation or fallback to Pi on a malformed response.
- Request identity: `sessionId` and `traceId` remain stable across a **rerun resuming the same session**. `requestId` and GitHub `run.attempt` identify each invocation. `run.runId` links to Actions workflow run, and `run.jobId` to its concrete job; a fresh separate task/job uses its own sessionId. A retry inside a session is an agent/tool event, **not** a second root Koog session. No second concurrent lease is allowed.
- `repository.baselineSha`, `headSha`, `worktreeId`, protected paths, writable paths and `toolPolicy.policySha256` are trusted frozen inputs. Protected scope includes Git metadata, control checkout, the active workflow, agent policy, and stage-owned specs/tests even if omitted in a sample. Tool enforcement must canonicalize paths/symlinks and enforce deny precedence. String patterns in a request are **not sufficient** authorization. All worktree paths and artifact destinations must be contained in their pre-authorized root.
- `model.credentialRef` is an **env-var name reference**, never a credential value; adapter obtains it from a trusted runner secret store and restricts child environment. `model.baseUrl` is a resolved, allowlisted endpoint. Koog may neither change it nor contact arbitrary hosts. All budgets, including nested agents, are bounded by a shared deadline, token total, tool count, max depth and child count. Unavailable accounting marks usage incomplete, never zero for billing claims.
- `resume.mode=fresh` requires null checkpoint; `resume.mode=resume` requires a content-hashed durable checkpoint. A **new strictly greater fencing generation** and exclusive lease from GitHub precede resuming. Compare request, stored session ID, baseline SHA, canonical worktree identity and digest, policy hash, journal and artifact hashes, and checkpoint version. Reject mismatches; never replay unknown writes or unresolved tool side effects. Recoverable effects require unique `toolExecutionId` idempotency keys and explicit reconciliation, not a blind retry. A rerun without valid durable state is **rejected/needs-human**, not a fresh run against a partially written worktree.
- Terminal result status: `succeeded`, `failed`, `cancelled`, `timed_out`, `rejected`. Non-success must include a structured, sanitized SessionError (`code`, `category`, `retryable`, `safeMessage`); success has `error=null`. Status is terminal and unique per request/fence. A successful Koog run can still fail outer trusted validation or receive CHANGES_REQUESTED. A cancellation must propagate to child agents, pending tools and provider calls; the adapter must write or recover a non-success result and release the lease.
- Session-state machine: `created → accepted → running`; `running → checkpointing → running|paused`; `paused → resuming → running`; any active state → `failed|cancelled|timed_out`, while admission can → `rejected`; `running → succeeded`. Terminal states have no outgoing transitions; sequence numbers increase strictly for **one logical session**, including resume. On restart the first resumed event references the previous checkpoint event as causation. Every child session/agent and every tool invocation has distinct `agentId`/`toolExecutionId`, a parent, `correlationId` and `causationId` so event ancestry can be reconstructed without hidden model reasoning.
- Events are append-only JSONL, one schema-valid envelope per line. Record sanitized model request/response metadata, available usage, provider timings, tool start/result, authorization denial, agent spawn/completion, state transitions, checkpoint references and errors. `redaction.mode` records applied policy. No raw credentials, authorization headers, user secrets, raw prompt or hidden chain-of-thought in events, console, CI summaries, checkpoint metadata or PR comments. Optional content diagnostics are separate restricted artifacts with independent explicit allowlisting/redaction.
- Checkpoint writes are atomic: persist immutable snapshots and tool side-effect journal, fsync durable store, then publish a manifest/digest and monotonic sequence. **Checkpoints are inert data** until trusted adapter validates lease/fence, hashes and baseline. Restrict stored transcripts to sanitized/scope-permitted data. `unresolvedSideEffectIds` blocks automatic replay. Artifact references require digest verification (size/path/content and path root), not just existence.
- Default retention proposal: structured sanitized session events and summary **14 days**, restricted raw provider traces **7 days** to match existing Pi implementation traces, checkpoints **until terminal + 7 days** or explicit operator hold, subject to runner/evidence volume and Actions artifact retention policies. Retention is a policy to implement in later tasks, **not** a claim that current GitHub workflows already enforce it. Credentials are never retained. Operator holds must be permissioned, logged and time-bounded.

## Backend compatibility and rollback

Currently `scripts/pi-run-stage.mjs` builds an in-process StageRunSpec via `stage-run-contract.mjs`, selects Pi or experimental mini-swe and returns a `succeeded` StageRunResult (other failures throw). That **existing local adapter contract does not carry** a durable session ID, protected paths, checkpoint hash or fencing. #789 must introduce an **explicit adapter** (not reinterpret StageRunSpec as SessionRequest) to map stage selection to a new protocol and translate accepted SessionResult into the already validated legacy terminal/metrics artifacts. GitHub remains the sole writer of the trusted publication and review metadata.

A backend choice is read once per job from an explicit trusted configuration, initially `pi` by default; `koog` is allowlisted and pinned to distribution SHA + schema major/minor + capabilities. Log chosen backend, version, model and request ID. Do **not** change workflow names, permissions, run-on labels, `PI_AUTOMATION_MODE`, issue/PR labels, branch convention, runner watcher names or Merge Gate rules. A failed/malformed Koog result fails closed and may be retried by a **new trusted job** with a new fence, never silently executes Pi in the same worktree/attempt. An operator can flip **one configuration value back to Pi for future new jobs**; a pending Koog checkpoint cannot be interpreted as a Pi checkpoint. Discarding it requires an explicit, separately approved recovery/new-worktree decision.

Rollout is gated: contract/fake-runtime tests (#785), immutable spec/test and tool enforcement (#787), resume/side-effect fault tests (#788), comparable disposable pack and opt-in Actions adapter (#789), shadow/canary rollback (#790), then **separate** decision to retire Pi. Each gate leaves existing Pi workflow unmodified until reviewed.

## Four-workflow smoke comparison fixtures

Use the **four independently isolated E2E tasks** most recently defined in #770–#773, with historic #760–#763 and diagnostic #769 as immutable comparison records. The cases are **WeatherService / Open-Meteo**, **CSV Expense CLI**, **Snake**, and **Arkanoid / Breakout**. The acceptance wording, protected file paths and source issue body are inputs; record their content SHA-256 at each replay. Replays need fresh numbered issues, worktrees, branches, paths and checkpoints; previous PRs/results are **evidence only**. Do not transplant old code or use previous model output as a starting checkpoint.

For each backend/run record dev baseline SHA at start, exact issue/spec hash, backend release+protocol version, model ID and endpoint, attempt/session/trace IDs, policy hash, tool denies, completed/failed stages, child count, total tokens **with completeness flag**, wall time, retries, validation/Reviewer/CI outcome, resulting PR/commit and sanitized artifact hashes. Compare correctness and safety first; token or duration comparisons are meaningful only when both runs use the same provider/config and complete telemetry. A backend **success** without valid terminal artifact or the same trusted independent checks does not count as equivalent. Neither this document nor #784 starts these jobs.
