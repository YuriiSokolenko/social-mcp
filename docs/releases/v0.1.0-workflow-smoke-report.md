## Вывод

По качеству второй пакет заметно лучше первого. Главное достижение этой итерации — не скорость и не резкое снижение token cost, а повышение вероятности получить правильное законченное решение.

Особенно хорошо это видно по #397: ошибка focused validation была исправлена, exact failed scope был повторён, и workflow завершился VERIFIED. В первом пакете соответствующая задача #342 закончилась `VERIFICATION_FAILED`.

Также второй пакет устранил полный abort, наблюдавшийся в #344: соответствующий повтор #399 дошёл до корректного результата и получил reviewer PASS. Однако #399 показал новый главный bottleneck — pathological recovery/context loop: 43 main responses, 40 tool calls, 5 попыток `submit_result`, несколько coding-session/cleanup циклов и более 1.1M main-agent токенов.

Два наиболее важных оставшихся дефекта harness на момент v0.1.0:

1. **Scope hygiene / publication gate (#396).** Workflow смог завершиться VERIFIED, хотя в PR попал случайный `.pi-tmp-placeholder.py`. Независимый reviewer поймал этот дефект и запросил изменения.
2. **Pathological recovery loop (#399).** Финальный код корректен, но harness потратил непропорционально большой объём model context и tool churn на cleanup/recovery.

Итоговая оценка релизного состояния:

> **Correctness и recovery заметно улучшились. Типичный token cost почти не изменился. Основные следующие цели — жёстче контролировать publish scope и устранять pathological recovery loops без снижения качества решения.**
