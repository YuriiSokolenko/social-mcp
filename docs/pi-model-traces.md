# Pi model request and response traces

The Pi Implementer workflow uploads `pi-model-trace-implementer-<issue>-<run-id>-<attempt>` as a GitHub Actions artifact with **7 day retention**. Seven days is the retention policy for full Pi model traces: it keeps traces available for routine cross-iteration workflow analysis and regression diagnosis without retaining prompt/response payloads indefinitely. Implementer is currently the only Pi stage that uploads model-trace artifacts; Reviewer, Architect, Triage, and Dispatcher do not yet publish them, so there is no stage-specific retention exception today. The stage segment is part of the canonical name for reuse by other stages. The JSONL file is written incrementally under `$RUNNER_TEMP`; each line is one model HTTP exchange, with a monotonically increasing `sequence` to order concurrent calls. Download it from the completed workflow's **Artifacts** section. The artifact is uploaded with `if: always()` and is skipped only when no trace file was created. Traces are temporary debugging material.

Each record contains `sequence`, `timestamp`, `stage`, `issue`, `model` (`provider`, `id`, and base URL), `request` (`method`, path, and body), `response`, HTTP `status`, and `elapsedMs`. A transport failure has `response: null` and an `error` with its name and message. Transport connection failures use status `502`, client disconnects use `499`, and request timeouts use `504`. Non-2xx upstream HTTP responses retain their status and response body and include an `HttpError` summary. If recording reaches the 100 MiB per-run limit, the trace stops after writing a `traceLimitReached` record; complete earlier exchanges are retained, and no exchange is silently truncated.

Model traces can contain full prompt and repository content, model responses, tool schemas, tool results, file contents, and command output. Treat the artifact itself as sensitive even though transport credentials are redacted. Because this is a public repository, assume its artifacts can be downloaded by any signed-in GitHub user. Transport headers are not stored, which excludes authorization, API keys, cookies, and other headers. URL user information, query strings, and fragments are removed from the recorded base URL; credential-like query parameters in the request path are redacted. Credential fields such as authorization, API keys, access/refresh/id tokens, client secrets, passwords, and cookies are replaced with `[REDACTED]`. Usage fields such as `max_tokens`, `prompt_tokens`, `completion_tokens`, and `total_tokens` remain visible. Text values redact bearer credentials, common `sk-...` keys, and credential assignments such as `access_token=...`, while ordinary prose such as `token: counter` is preserved. Other prompt and response content is preserved. The proxy forwards original headers and bodies to the configured endpoint; redaction applies only to the trace. Trace writes are best effort and do not fail model calls.

Streaming/SSE responses are stored as the complete raw response text for the HTTP exchange. Streaming events are not normalized into separate trace records.

Payloads never go to the Actions console. This initial artifact integration is enabled for Pi Implementer runs; the same proxy can be enabled for other Pi stages by routing them through `pi-run-stage.mjs`.
