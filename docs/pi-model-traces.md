# Pi model request and response traces

The Pi Implementer workflow uploads `pi-model-trace-<issue>-<run-id>-<attempt>` as a GitHub Actions artifact (14 day retention). The JSONL file is written incrementally under `$RUNNER_TEMP`; each line is one model HTTP exchange, with a monotonically increasing `sequence` to order concurrent calls. Download it from the completed workflow's **Artifacts** section. The artifact is uploaded with `if: always()` and is skipped only when no trace file was created.

Each record contains `sequence`, `timestamp`, `stage`, `issue`, `model` (`provider`, `id`, and base URL), `request` (`method`, path, and body), `response`, HTTP `status`, and `elapsedMs`. A transport failure has `response: null` and an `error` with its name and message. Non-2xx HTTP responses retain their status and response body and include an `HttpError` summary. If recording reaches the 100 MiB per-run limit, the trace stops after writing a `traceLimitReached` record; complete earlier exchanges are retained, and no exchange is silently truncated.

Transport headers are not stored, which excludes authorization, API keys, cookies, and other headers. URL user information, query strings, and fragments are removed from the recorded base URL; credential-like query parameters in the request path are redacted. JSON fields whose names contain `authorization`, `api_key`, `token`, `secret`, `password`, or `cookie` are replaced with `[REDACTED]`. Text values redact bearer credentials, common `sk-...` keys, and credential assignments such as `access_token=...`. Other prompt and response content is preserved. The proxy forwards original headers and bodies to the configured endpoint; redaction applies only to the trace. Trace writes are best effort and do not fail model calls.

Payloads never go to the Actions console. This initial artifact integration is enabled for Pi Implementer runs; the same proxy can be enabled for other Pi stages by routing them through `pi-run-stage.mjs`.
