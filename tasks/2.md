# Threads: Meta app configuration, scopes and OAuth documentation

## Scope and acceptance
## Goal
Document the Meta/Threads OAuth flow, required minimum scopes, callback handling, token exchange, long-lived token lifecycle, refresh behavior, and safe local storage. Verify current official endpoints and scopes during implementation. No secrets in Git.

## Acceptance criteria
- META_APP_ID and META_APP_SECRET configuration is present and documented in .env.example (empty values, no real secrets).
- The Threads/Meta OAuth flow is documented end-to-end: authorization URL, required minimum scopes, callback handling, token exchange, long-lived token lifecycle, and refresh behavior.
- Safe local storage strategy (encrypted at rest via TOKEN_ENCRYPTION_KEY, key outside database and Git) is documented.
- No OAuth tokens, client secrets, or encryption keys are committed to the repository.
- Implementation tasks for callback handling, token exchange, and token lifecycle are tracked in issues #15, #16, and #17 respectively.

## Tests
N/A — documentation and configuration only; no code changes required.

## Out of scope
OAuth callback handling, token exchange, encrypted token persistence, and token lifecycle implementation (covered by issues #15, #16, and #17).
