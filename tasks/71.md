# Implement threads_reply write tool

## Scope and acceptance
## Goal
Implement the `threads_reply` MCP write tool for publishing a reply to a Threads post, following docs/threads-tool-contract.md and the confirmation boundary.

## Acceptance criteria
- Implement `threads_reply` with inputs `post_id` (required), `text` (required), and optional media.
- Validate inputs and return normalized errors: `invalid_request`, `not_found`, `permission_required`, `capability_unavailable`, `rate_limited`, `platform_error`.
- Treat this as an explicit write: refuse execution until the MCP client confirms explicit user intent for that reply.
- Keep platform API details inside the Threads adapter; keep the MCP layer thin.
- Return the created reply identifier and a safe normalized status.

## Tests
Cover authorized replies, input validation errors, missing/unauthorized scopes, and rate-limited or temporary platform failures with mocked HTTP boundaries. Tests must not perform live Threads writes. Run pytest and Ruff.

## Out of scope
No repost, quote, delete, or moderation actions (split into separate issues). No new OAuth flow or credential handling. No live platform API calls in CI.
