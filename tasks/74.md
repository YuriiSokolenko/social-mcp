# Implement threads_manage_reply write tool

## Scope and acceptance
## Goal
Implement the `threads_manage_reply` MCP write tool for supported moderation/management actions on a Threads reply, following docs/threads-tool-contract.md and the confirmation boundary.

## Acceptance criteria
- Implement `threads_manage_reply` with inputs `reply_id` (required) and `action` (required, from an explicit enum of implemented API actions).
- Define the action enum based on the current official Threads API capabilities for reply management.
- Validate inputs and return normalized errors: `invalid_request`, `not_found`, `permission_required`, `capability_unavailable`, `rate_limited`, `platform_error`.
- Treat actions as explicit writes requiring client confirmation before execution.
- Keep platform API details inside the Threads adapter; keep the MCP layer thin.

## Tests
Cover authorized actions, invalid or unknown actions, missing scopes, and platform or rate-limit errors with mocked HTTP boundaries. Tests must not perform live Threads writes. Run pytest and Ruff.

## Out of scope
No reply publishing, repost/quote, or delete actions (split into separate issues). No new OAuth flow or credential handling. No live platform API calls in CI.
