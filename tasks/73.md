# Implement threads_delete write tool

## Scope and acceptance
## Goal
Implement the `threads_delete` MCP write tool for deleting content owned by the connected Threads account, following docs/threads-tool-contract.md and the confirmation boundary.

## Acceptance criteria
- Implement `threads_delete` with input `post_id` (required).
- Enforce that deletion applies only to content owned by the connected account.
- Validate inputs and return normalized errors: `invalid_request`, `not_found`, `permission_required`, `capability_unavailable`, `rate_limited`, `platform_error`.
- Treat deletion as a destructive explicit write requiring especially clear client/agent confirmation before execution.
- Keep platform API details inside the Threads adapter; keep the MCP layer thin.

## Tests
Cover successful deletion of owned content, denial of deletion for non-owned content, missing scopes, and platform or rate-limit errors with mocked HTTP boundaries. Tests must not perform live Threads writes. Run pytest and Ruff.

## Out of scope
No reply, repost/quote, or moderation actions (split into separate issues). No new OAuth flow or credential handling. No live platform API calls in CI.
