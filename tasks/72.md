# Implement threads_repost and threads_quote write tools

## Scope and acceptance
## Goal
Implement the `threads_repost` and `threads_quote` MCP write tools for resharing Threads content, following docs/threads-tool-contract.md and the confirmation boundary.

## Acceptance criteria
- Implement `threads_repost` with input `post_id` (required).
- Implement `threads_quote` with inputs `post_id` (required), `text` (required), and optional media.
- Validate inputs and return normalized errors: `invalid_request`, `not_found`, `permission_required`, `capability_unavailable`, `rate_limited`, `platform_error`.
- Treat both operations as explicit writes requiring client-confirmed user intent before execution.
- Keep platform API details inside the Threads adapter; keep the MCP layer thin.
- Return created object identifiers and safe normalized status.

## Tests
Cover authorized repost/quote, input validation, missing/unauthorized scopes, and platform or rate-limit errors with mocked HTTP boundaries. Tests must not perform live Threads writes. Run pytest and Ruff.

## Out of scope
No reply, delete, or moderation actions (split into separate issues). No new OAuth flow or credential handling. No live platform API calls in CI.
